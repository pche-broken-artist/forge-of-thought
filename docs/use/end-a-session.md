# End a session

`/end` closes a working session by telling you what a shutdown would lose. It is for you, the principal (the person whose thinking is being forged), when you are about to close the command line and want to know that nothing is lost. A session here is one run of Claude's conversation with you.

## When to use it

Run `/end` before you close the command line. Use it whenever you are not sure that what you agreed in the conversation has reached a file.

## The command

```
/end
```

The command takes no argument.

## What happens

`/end` writes nothing and runs nothing but the status script. Every remedy it names is an offer, never an action.

1. Claude says what lives only in this conversation. That means a round of work not yet written, verdicts carried toward a write, and anything promised and not done. Claude offers the write of what is agreed so far.

   You should now see a list of what exists only in the conversation, with the offer to write it, or a statement that there is nothing of the kind.

2. Claude runs the status script without the remote. The script reads the state of the engine and of each project, and it touches no network. For each repository it prints the unsaved changes or "clean - nothing to save", the branch, the last commit and the origin. Claude names every repository with unsaved changes and offers `/save` for them (see [Save your work](save-your-work.md)).

   You should now see each repository with unsaved changes named, with the offer of `/save`, or the plain fact that every repository is clean.

3. Claude names stale renders as a fact. It reads them from the Renders table of the ledger, the file that records the state of the project. A render is a generated output made from a recipe. Claude makes no offer here, because renders are regenerated by a release.

   You should now see the stale renders named, or no mention of any.

4. Claude closes with one sentence. It says either that nothing lives only in this conversation and that shutting the command line loses nothing, or it lists what a shutdown would lose.

   You should now see that one closing sentence.

## What you have afterwards

You know what a shutdown would lose, and you have an offer for each thing that would be lost. Nothing has changed on disk. If you want the offered write or save, you give the word and Claude does it.

State lives in files and never in the conversation. The reason is in [Documents and records](../about/documents-and-records.md). The terms used here are in the [Glossary](../reference/glossary.md).

## If something goes wrong

The status script reports a repository that is "not under git" as such. That is a property of the project, not a defect, and `/end` has nothing to offer for it.

The messages the script prints on a missing git or a missing engine repository are not recorded in the inputs of this page.

## A worked example

A generic closing, with a placeholder project `my-project`.

Claude says that one round on the intent is agreed but not written, and offers the write. The status script then shows `my-project` with unsaved changes, and Claude offers `/save my-project`. No render is stale. Claude closes:

> Shutting the command line now would lose the agreed round on the intent, which is not written yet, and the unsaved changes in `my-project`.

After you give the word for the write and the save, running `/end` again closes with:

> Nothing lives only in this conversation, and shutting the command line loses nothing.
