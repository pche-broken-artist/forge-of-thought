# Requirement style

The Requirement style is the rule set for writing the items of an assignment, the document that hands the work to its recipients. This page is for the person who reads or writes an assignment and for the extender who needs the rules exactly. Terms of the forge are explained in the [Glossary](glossary.md); the reasons for the rules are on the page [The assignment](../about/the-assignment.md).

## The rules

| Rule | What it says |
|---|---|
| Modal verbs | Items use **shall** and **shall not**. |
| Banned words | `would`, `could`, `should`, `might`, `may` and MoSCoW wording are not used. |
| Priorities | There is no priority column and there are no priority tags. Every item is essential by default. |
| Exceptions | An item that is not essential carries a note reading *optional*. |
| One idea | Each item covers one idea. |
| Written once | Each item is written once. |
| Full sentences | Each item is written in full, correct sentences. |
| Testability | Testability is recommended, not required. Assignments are deliberately high-level. Delegating the concretisation through a deliverable item is a legitimate outcome. |
| Defined terms | A defined term is capitalised in the item text, to signal that it appears in the Terms section. |
| External links | An item must not depend on an external link to be understood, agreed or later tested. |
