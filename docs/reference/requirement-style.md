# Requirement style

This page lists the rules for writing the items of an assignment. It is
for the person who reads or edits an assignment and for the one who
extends the forge with a layer that writes items of its own.

The items of an assignment are written with **shall** and **shall
not** and carry no priorities. The rule set belongs to the definition
of the assignment; the engine's core instructions point to it.

## Rules

| Rule | What it says |
|---|---|
| Modal verbs | Use **shall** and **shall not**. Do not use would, could, should, might, may, or MoSCoW wording. |
| Priorities | There is no priority column and there are no priority tags. Everything in an assignment is essential by default. |
| Exceptions | An item that is not essential is marked by a note reading *optional* on that item. |
| One idea | Each item covers one idea. |
| Written once | Each item is written once. |
| Full sentences | Each item is written in full, correct sentences. |
| Testability | Testability is recommended, not required. Assignments are deliberately high-level, and delegating concretisation through a deliverable item is a legitimate outcome. |
| Defined terms | Defined terms are capitalised in the item text, to signal that they appear in the Terms section. |
| External links | An item must not depend on an external link to be understood, agreed or later tested. |
