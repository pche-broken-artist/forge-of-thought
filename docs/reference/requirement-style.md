# Requirement style

This page lists the rules for writing the items of an assignment. It is for the person who reads or edits an assignment and for the one who extends the forge. The rule set belongs to the assignment's definition, `.claude/skills/forge/states/assignment.md`, and the core instructions in `CLAUDE.md` point to it.

## Rules

| Rule | What it says |
|---|---|
| Modal verbs | Items use **shall** and **shall not**. |
| Banned words | would, could, should, might, may, and MoSCoW wording are not used. |
| Priorities | There is no priority column and there are no priority tags. Everything in an assignment is essential by default. |
| Exceptions | An exception is marked by a note reading *optional* on that item. |
| One idea | Each item covers one idea. |
| Written once | Each item is written once. |
| Sentences | Each item is written in full, correct sentences. |
| Testability | Recommended, not required. Assignments are deliberately high-level, and delegating concretisation through a `DEL` item is a legitimate outcome. |
| Defined terms | A defined term is capitalised in item text, to signal that it appears in the Terms section. |
| External links | An item does not depend on an external link to be understood, agreed or later tested. |
