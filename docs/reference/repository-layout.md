# Repository layout

This page lists the files of the engine root, of a thought project
and of a library, one by one, each with what it is for. It is for the
user who looks for a file, the extender who adds one and the
evaluator who wants to see what the forge keeps where. The engine is
the repository that holds the forge's skills, scripts and templates;
a project is a repository of its own that holds one thought.

## The entries of the root that carry a rule

- `SECURITY.md`: the security policy, the principal's own text, no
  render.
- `CODE_OF_CONDUCT.md`: the code of conduct, the Contributor
  Covenant 3.0 word for word, no render.
- `tmp/`: the engine's working folder. It holds packets, envelopes
  and profiles of runs on another engine (`tmp/research/<run>/`),
  the tasks of a documentation run, dry ledgers, the manifest of a
  migration and check reports before filing. It is in git with its
  own README and `.gitignore`, its contents never. It is no source of
  truth and no check, ledger or history reads it.
- `templates/`: canonical skeletons.
- `projects/`: gitignored (`projects/*`) but for its README. Every
  project is a git repository of its own, which the engine does not
  know. The forge's own project, `projects/forge`, is among them.

## A library

A project of kind library holds material shared across projects. It
has no chain: only the project file, the attributes, the ignore of
the ledger, sources and research. Its documents are maintained by
their owner. Its README is the catalogue, a render of its recipe.

```
projects/lib-<name>/       # kind: library - material shared across
  .git/  project.md        # projects, no chain: only the project
  .gitattributes           # file, the attributes, the ignore of
  .gitignore  ledger.md    # the ledger, sources and research; documents
  README.md  logo.png      # maintained by their owner; README =
  recipes/readme.md        # the catalogue, a render of its recipe
  recipes/readme.history.md
  sources/00-INDEX.md
  research/00-INDEX.md
```
