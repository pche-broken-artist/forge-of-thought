# Repository layout

This page lists the files and folders of the engine root, of a thought
project and of a library, one line each, as the layout block of the
engine's `CLAUDE.md` gives them. It is for anyone who needs to know
where a file lives and what it is. A project is the unit of work under
`projects/`; the principal is the person whose thinking is forged in
it; the ledger is the file that holds a project's state, made from its
documents when it is read.

### The scripts

`scripts/` holds these scripts and modules, as its comment in the
layout names them:

- `forge-save`, `forge-pull`, `forge-status`, `forge-clone`,
  `forge-branch`: git, and what waits on GitHub.
- `forge-history`: the history of one item.
- `forge-report`: the unique name of a report.
- `forge-ledger`: the ledger made at read time.
- `forge-migrate`: a project brought to the shape of a release.
- `forge-config`: the user's global git configuration through git,
  that is the registration of the merge driver ours and its settings,
  the guard, the identity per host.
- `forge-check`: the mechanical clauses of a check as a program, with
  its module `forge_check`.
- `forge-engine`: one packet run on a model of another family over its
  CLI, the answer back as a note.
- `forge-cite`: every URL of a note opened before it is filed;
  `forge-engine` and `forge-cite` both serve the brief research.
- `doc2md`: document to Markdown.
- `md2pptx`: deck render to PowerPoint.
- `md2docx`: render to Word.
- `md2pptx` and `md2docx` each work by pandoc or by a model.
- `md2video`: screenplay render to video or player events.
- `hook-walkthrough`: the per-prompt hook of `.claude/settings.json`.
- `hook-git`: the wall between reading git and writing it, a
  PreToolUse hook of the same file.
- `docs-state`, `docs-index`, `docs-check`: the documentation, that is
  the state of its pages, its index, its check.

The five modules the scripts share are `forge_repos`, `forge_tools`,
`forge_docs`, `docs_map` and `forge_check`.
