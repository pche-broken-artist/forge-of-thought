A third kind of project, `workshop`: a project that uses the
forge's functionality without working on the artefacts of the
chain. The case is forge-rollout: a place where the forge's own
mechanics are used on the ad hoc tasks of promoting the forge (a
video, then presentations, another video, the CTO pitch brought
up to date), with no assignment to find and no intent to grow;
today it runs as a thought project whose main brief is empty and
whose brief `video-tutorials` 0.3 will never be mined. The unit of
work in a workshop is a thread: one task the principal wants done
there, opened when it arises, worked in its file, closed when
done; the open threads are the project's to-do list and the
ledger shows them as what waits on him. A brief is allowed for a
larger whole as his text of what he wants and why, never mined.
Everything else stays available: research, ingest, recipes and
renders, published files, work products, the critic, the checks.
What the kind must settle: how a thread is born and closed without
an intent, since today both run through `/forge intent` and the
closing record lives in the intent's history (POS.1680); which
tables the ledger keeps (Briefs without Mined, no Documents); what
`/forge` maps for it (no target states); that a brief without an
intent is no finding of a check (FND.0040 of forge-rollout parked
on exactly that); `/new-project`, `/release` and the genres readme
and release-notes, which today know only `thought` and `library`
(POS.0960, POS.0970); and how an existing project changes kind,
since the project file is written once (POS.1590). The name
`workshop` is decided; `framework` was weighed and dropped, since
the framework is the forge itself. Opened 2026-10-24.
