### FND.0050 [medium] [gap]
- **Location:** 10-intent.md POS.0830 vs CLAUDE.md (Persistence,
  Repository layout — `scripts/` line) and `scripts/*.ps1`
- **Issue:** POS.0830 fixes a rule that "is a writing rule, not a claim"
  until verified on Linux: scripts are PowerShell 7 written with nothing
  Windows-only, usage examples included, instance facts to move out. The
  core — the handover artefact whose reader is the agent that edits the
  scripts — carries none of it: CLAUDE.md never states that scripts are
  cross-platform PowerShell 7, that Windows-only constructs are banned,
  or that instance facts do not belong in them. Meanwhile the scripts on
  disk still show what the rule forbids: `doc2md.ps1` and `md2pptx.ps1`
  help text uses `C:\data`, `C:\out` examples, and `forge-save.ps1`
  hard-codes the remote URL, author name and e-mail (lines 28, 50–51).
- **Why it matters:** A writing rule that lives only in the intent binds
  nobody at the moment of writing; the next script edit will be made
  against CLAUDE.md, which is silent, and the observed nonconformance
  will persist or grow. The hard-coded instance facts also sit inside
  what POS.0760 declares the public engine ("must contain no
  company-specific data"), so the gap is not only stylistic.
- **Suggested fix:** Add the rule to CLAUDE.md (Persistence or Layout:
  scripts are cross-platform PowerShell 7, nothing Windows-only, no
  instance facts, examples platform-neutral), and either fix the
  examples now or record their move as an explicit open item rather than
  an aside inside POS.0830 (it is currently "tied to THR.0090", a thread
  that is "deliberately not being worked on").

### FND.0060 [low] [contradiction]
- **Location:** 10-intent.md Essence ("Two independent AI reviewers …
  from two different angles"); CLAUDE.md heading "Two independent
  reviewers" and line 8 ("independent adversarial review"); README §7
  ("Two kinds of independent reviewers") — vs POS.0790
- **Issue:** POS.0790 is titled "Isolation is not independence" and
  states that the reviewers share one model family and that their
  agreement is never validation; the Essence and the core's headings go
  on calling the same reviewers "independent". POS.0400 ("two
  independent *kinds* of review") is defensible; "independent
  reviewers" is exactly the claim POS.0790 retracts.
- **Why it matters:** The word carries the promise CHL.0020 attacked and
  the principal accepted. An outward reader of CLAUDE.md or the README
  is told the opposite of what the intent now holds, and the different-
  family challengers (POS.0800) become inexplicable as a plan.
- **Suggested fix:** Reword to "isolated" / "blind" (which is what the
  text goes on to describe anyway) in the Essence, the CLAUDE.md heading
  and, via the recipe or its inputs, README §7; keep "independent" for
  the planned different-family challengers only.

### FND.0070 [low] [divergence]
- **Location:** README.md (rendered 2026-08-18 from intent v2.8) —
  title, §7, command-table paragraph on `/ingest` (line 337–342),
  prerequisites — vs 10-intent.md v2.9–2.11
- **Issue:** The README on disk states a convention the intent has
  since reversed: `/ingest` "registers its free-text purpose in the

- **Why it matters:** The README is the outward handover artefact of

  unconditional re-render at the next `/save` touching `projects/forge/`),
  so the finding records the state, not a missing mechanism — it exists
  so the next run can verify the re-render actually carried POS.0830
  and POS.0840.
- **Suggested fix:** `/render readme` (never a hand edit), then confirm
  the regenerated text drops "purpose in the ledger" and mentions the
  material indexes; ledger Renders row updated to the new provenance.
