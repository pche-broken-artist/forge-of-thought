# Repository layout — the root of the engine

The root of the engine, file by file, each with what it is for; the
entries that carry a rule and the layout of a project and of a library
stand in CLAUDE.md, Repository layout, which names this file.

```
CLAUDE.md                  # the universal core
CLAUDE.local.md            # instance facts (CLAUDE.md, What this
                           # workspace is)
README.md                  # for humans — a render (/render readme)
RELEASE-NOTES.md           # release notes — a render (/render
                           # release-notes); the shape:
                           # templates/recipe-release-notes.md
CONTRIBUTING.md            # for a visitor who wants to say, ask or
                           # change something — a render (/render
                           # contributing)
SECURITY.md                # CLAUDE.md, Repository layout
CODE_OF_CONDUCT.md         # CLAUDE.md, Repository layout
docs/                      # the documentation, generated by
                           # /document: pages of one topic each and
                           # their index, from the map docs-map.md
                           # beside the owning project's ledger;
                           # docs/videos/: the public folder of the
                           # projects' html-player files and the
                           # player page index.html, written from
                           # templates/html-player.html by md2video;
                           # docs/.nojekyll keeps GitHub Pages from
                           # touching it
logo.png                   # project avatar
LICENSE                    # CC BY 4.0 — the engine is published
                           # under attribution
.gitattributes             # the engine's own ways of merging by
                           # path, its derived files at the root
.gitignore                 # what never enters the engine's git: the
                           # instance file, the local settings, every
                           # project but the README of projects/
                           # (POS.1980), the noise of the operating
                           # systems, Office lock files, the caches
                           # of Python's tools
.mailmap                   # the author's names in the history
                           # mapped to one handle; git's own
                           # mechanism, the history untouched
scripts/                   # forge-save / forge-pull / forge-status
                           # (git, and what waits on GitHub)
                           # / forge-clone / forge-branch (git),
                           # forge-github (one issue or discussion
                           # of the origin read, one reply posted),
                           # forge-ci (how what GitHub ran on the
                           # origin's head ended, waited for after
                           # a push),
                           # forge-history (the history of one
                           # item), forge-report (the unique name
                           # of a report), forge-record (a record
                           # or a decision appended at the end of
                           # its file), forge-ledger (the ledger
                           # made at read time), forge-migrate (a
                           # project brought to the shape of a
                           # release), forge-config (the user's
                           # global git configuration through git:
                           # the registration of the merge driver ours and
                           # its settings, the
                           # guard, the identity per host),
                           # forge-check (the mechanical clauses of
                           # a check as a program, with its module
                           # forge_check; the trial of THR.0530),
                           # forge-engine (one packet run on a model
                           # of another family over its CLI, the
                           # answer back as a note), forge-cite
                           # (every URL of a note opened before it
                           # is filed; both of the brief research),
                           # doc2md
                           # (document →
                           # Markdown), md2pptx (deck render →
                           # PowerPoint), md2docx (render → Word),
                           # each by pandoc or by a model, md2video
                           # (screenplay render → video or player
                           # events),
                           # hook-walkthrough (the per-prompt hook
                           # of .claude/settings.json), hook-git
                           # (the wall between reading git and
                           # writing it, a PreToolUse hook of the
                           # same file), docs-state,
                           # docs-index and docs-check (the
                           # documentation: the state of its pages,
                           # its index, its check); forge_repos,
                           # forge_tools, forge_docs, docs_map and
                           # forge_check
                           # the modules the scripts share
                           # (CLAUDE.md, Persistence, Portability)
tests/                     # the engine's tests (POS.1930): pytest
                           # over tests/, conftest.py with what they
                           # share, tests/fixture the synthetic
                           # fixture project copied by every test
                           # (POS.1940); run by /test
pytest.ini                 # how pytest runs them: tests/ as the
                           # path, scripts/ on the import path
.github/workflows/tests.yml  # CI: the tests at every push and pull
                           # request, Linux and Windows, Python 3.8
                           # and the newest (POS.1960)
tmp/                       # CLAUDE.md, Repository layout
.claude/                   # skills (the commands, the contracts of
                           # the reviewers and of the documentation
                           # agents, and the walkthrough method),
                           # agents (the reviewers, the
                           # documentation's planner and writer),
                           # reference (what is read on demand:
                           # the table of commands, the table of
                           # prefixes and this layout),
                           # settings (settings.json: the two
                           # hooks, the deny rule of the other
                           # shell, the two denies of the user's
                           # sensitive paths and the attribution
                           # switched off, POS.1200, POS.1090;
                           # settings.local.json: the session
                           # model — gitignored)
templates/                 # CLAUDE.md, Repository layout
projects/                  # CLAUDE.md, Repository layout
```
